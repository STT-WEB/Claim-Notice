- **v1.5.0** (8 ก.ย. 2569) — **PIN: ระบบเป็นคนสร้างให้ โชว์ครั้งเดียว แล้วเจ้าตัวจำเอง**

  เบียร์: *"ผู้ใช้ & PIN ของทุกคนนั้นแหละ Candy เป็นคนสร้าง PIN ให้นะ แล้วก็คนคนนั้นต้องจำ PIN ของตัวเอง"*
  *"ตอน NOVA คือ พอกดขอ PIN ก็จะโชว์ให้พนักงานเห็นในหน้านั้นเลย แล้วเค้าก็จำกัน
  เพราะเบียร์จะไม่ให้ซ้ำ เพราะว่าแต่ละคนต้องจำของตัวเอง"*

  **ทำตาม STT NOVA ทุกอย่าง** — แท็บ "📝 ยังไม่มี PIN" เปลี่ยนเป็น **"📝 ขอ PIN"**
  1. ใส่รหัสพนักงาน → ระบบยืนยันว่าเจอในทะเบียน (โชว์ชื่อแบบปิดบางส่วน `นา••••ดา`)
  2. พิมพ์ชื่อ-สกุลเต็มให้ตรงทะเบียน → กด **"ขอ PIN ของฉัน"**
  3. **ระบบสุ่ม PIN 6 หลักให้ แล้วโชว์ตัวเลขใหญ่ ๆ บนหน้าจอครั้งเดียว** พร้อมคำเตือนว่าจะไม่โชว์อีก
  4. กด "จำแล้ว — เข้าสู่ระบบ" → เลขหายจากหน้าจอทันที ต้องพิมพ์ PIN เองรอบแรก **จะได้รู้ว่าจำได้จริง**

  **พนักงานเลือกเลขเองไม่ได้แล้ว** — `setupPin()` ถูกถอดออก เหลือ `requestPin()` ที่ระบบสุ่มให้อย่างเดียว

  **PIN ห้ามซ้ำ** (เบียร์สั่ง) — `newUniquePin_()` สุ่มแล้วเช็คกับทั้งทะเบียนก่อนทุกครั้ง
  และตัดเลขเดาง่ายทิ้ง (111111 · 123456 · 654321 · 121212)
  PIN ซ้ำ = ระบบแยกไม่ออกว่าใครเป็นคนกด ลายเซ็นบนเอกสารก็พิสูจน์อะไรไม่ได้

  **ขอได้ครั้งเดียวตลอดชีพ** — มี PIN แล้วขอใหม่ไม่ได้ · ลืมแล้วต้องแจ้งผู้ดูแลไปแก้ในชีต USERS
  **ไม่มีที่ไหนในระบบเปิดดู PIN ย้อนหลังได้** (ถอดหน้า "ผู้ใช้ & PIN" ไปแล้วตั้งแต่ v1.4.1)
  และ **LOG ไม่บันทึกตัวเลข PIN** — บันทึกแค่ว่าใครขอ เมื่อไหร่ (มีเทสต์ไล่อ่านทุกบรรทัด LOG ยืนยัน)

  **เปลี่ยนจากเดิม** — สิทธิ์ผู้บริหาร/ผู้อนุมัติ เคยขอเองไม่ได้ (v1.2.6) ตอนนี้ **ขอได้เหมือนกันหมด**
  ตามที่เบียร์สั่งว่า *"ของทุกคนนั้นแหละ"* · ด่านที่กันคนอื่นมาขอแทนคือ **ต้องพิมพ์ชื่อ-สกุลให้ตรงทะเบียน**
  (กติกาเดียวกับ NOVA) — ถ้าเบียร์อยากให้กลับไปกันสิทธิ์ผู้บริหารไว้เหมือนเดิม บอกได้ แก้บรรทัดเดียว

  **ทดสอบ** — e2e 134 ข้อ · guard 50 · syntax 4 ·
  กดใช้งานหน้าขอ PIN จริงทีละปุ่มเหมือนพนักงาน (ตรวจรหัส → ขอ PIN → เห็นเลข → กดจำแล้ว)
  ยืนยันว่ากดจำแล้ว **เลขหายจากหน้าจอจริง** (ค้นทั้งหน้าไม่เจอเลขนั้นแล้ว) · จอมือถือ 420px ไม่ล้น · JS error 0

- **v1.4.1** (8 ก.ย. 2569) — **ถอดหน้า PIN และ LOG ออกจากโปรแกรม · รายงาน HR เห็นเฉพาะที่ควรเห็น**

  **① ถอดหน้า "ผู้ใช้ & PIN" ออกทั้งหมด**
  เบียร์: *"ตามระบบ PIN ทาง Candy ต้องกำหนดให้สิ ลองไปดูของ NOVA และมันไม่ควรให้ใครเห็นด้วย เอาออกไปเลย"*
  ดู NOVA แล้ว — NOVA **ไม่มีหน้าจัดการ PIN** เลย PIN อยู่ในชีต USERS ผู้ดูแลแก้ในชีตโดยตรง
  งานเคลมทำตามให้เหมือนกัน · ลบทั้งเมนู หน้าจอ และ**คำสั่งฝั่งเซิร์ฟเวอร์** `listUsersPin()` / `adminSetPin()`
  → ไม่มีใครในโปรแกรมนี้เปิดดูรายชื่อ PIN หรือตั้ง PIN ให้คนอื่นได้อีกแล้ว แม้แต่ผู้ดูแล
  **สิ่งที่ยังอยู่:** พนักงานตั้ง PIN ของตัวเองครั้งแรกได้เหมือนเดิม ที่หน้าเข้าสู่ระบบ แท็บ "📝 ยังไม่มี PIN"
  (เป็น PIN ของเจ้าตัวเอง ไม่ใช่การดู PIN คนอื่น — และเป็นสิ่งที่เบียร์สั่งไว้เมื่อ 7 ก.ย.)

  **② ถอด "LOG ประวัติการใช้งาน" ออกจากโปรแกรม**
  ลบเมนู · หน้าจอ · ไทล์ในหน้ารายงาน และคำสั่ง `reportLog()` ทิ้ง
  **แต่ `log_()` ยังเขียนลงแท็บ LOG เหมือนเดิม** — ระบบนี้ใช้ไป 10-20 ปี ถ้าไม่มีร่องรอยว่าใครกดอะไรเมื่อไหร่
  ลายเซ็นที่ขึ้นบนเอกสารก็พิสูจน์อะไรไม่ได้ · เบียร์เปิด/ลบ LOG ได้ที่แท็บ LOG ในชีตโดยตรง (ลบแล้วเอกสารไม่หาย)

  **③ รายงานส่ง HR (หักเงินพนักงาน) — เห็นเฉพาะ HR · ผู้ดูแล · ผู้อนุมัติ**
  เบียร์: *"อันนี้จะมีแค่ HR กับ Admin และคนที่ Approve เห็น"* → **จัดซื้อไม่เห็นแล้ว**
  เพราะเป็นเรื่องหักเงินเดือนพนักงาน ไม่ใช่ต้นทุนงาน
  ล็อก 3 ชั้น: เมนูหน้าแรก (`hide:true` = ไม่ขึ้นเลย ไม่ใช่แค่จาง) · ไทล์ในหน้า All Data and Report · และฝั่งเซิร์ฟเวอร์

  **แถม — ไทล์ในหน้ารายงานเคยโชว์ให้ทุกคนเห็น** (กดแล้วเซิร์ฟเวอร์ค่อยปฏิเสธ)
  ตอนนี้ 3.4 ต้นทุน · 3.5 รวมยอดเรียกเก็บ · 3.7 ส่งบัญชี เช็คสิทธิ์เหมือนเมนูหน้าแรกแล้ว
  แค่ "เห็นหัวข้อ" ของเรื่องเงินก็ไม่เหมาะ

  **ทดสอบ** — e2e 132 ข้อ (แทนเทสต์ของฟีเจอร์ที่ถอดออก ด้วยเทสต์ที่ยืนยันว่ามัน **ไม่มีแล้วจริง ๆ**
  และเทสต์ว่า log_ ยังเขียนลงชีตอยู่) · guard 50 · syntax 4 ·
  เรนเดอร์หน้าจริงเทียบ 3 สิทธิ์ (ผู้ดูแล / จัดซื้อ / HR) → JS error 0

- **v1.4.0** (8 ก.ย. 2569) — **แม่แบบเช็คลิสต์เป็นทะเบียนในระบบ + คลังรูป STD ประจำรุ่น · ปรับช่องกรอก 2 หน้า**

  ### ① ทะเบียนแม่แบบเช็คลิสต์ (เมนูใหม่ 🧾)

  เบียร์: *"แม่แบบเช็คลิสต์ มันเหมือนต้องเป็นไฟล์ที่ต้องสร้างขึ้นมาในระบบไหม ว่าอันนี้คือแม่แบบมาตรฐาน
  ของแต่ละโมเดลไหม ... ต้องมี Template ให้เบียร์กรอกข้อมูล เช่น การตรวจแท็งค์ model นี้ ต้องตรวจอะไรบ้าง + รูปภาพ เป็นหัวข้อ ๆ"*

  เดิมหัวข้อเช็คลิสต์ฝังอยู่ในโค้ด เบียร์แก้เองไม่ได้ ตอนนี้ย้ายมาเป็นทะเบียนจริงในชีต 2 แท็บ `TPL` + `TPLIT`
  · **สร้าง / แก้ / ก๊อป / ปิดใช้แม่แบบ** ได้จากในระบบ (สิทธิ์ QC และผู้บริหาร)
  · **ผูกกับ MODEL** — พิมพ์รุ่นตอนเปิดใบตรวจ ระบบเลือกแม่แบบของรุ่นนั้นให้เอง
  · **แนบรูป STD ได้ทีละหัวข้อ** — นี่คือคลังรูป STD ประจำรุ่นที่ค้างไว้ตั้งแต่รอบก่อน
    ใส่ครั้งเดียวที่แม่แบบ **ทุกใบตรวจที่เปิดจากแม่แบบนี้ได้รูป STD ไปเทียบทันที** ไม่ต้องแนบใหม่ทุกใบ
  · ครั้งแรกสุดระบบย้ายแม่แบบเดิม 4 ชุดลงทะเบียนให้เอง (ไม่ยัดซ้ำ) — เบียร์เข้าไปแก้หัวข้อจริงต่อได้เลย
  · ปิดใช้แม่แบบ = ซ่อนจากตัวเลือก แต่ยังอยู่ในทะเบียน ใบเก่าที่อ้างชื่อไว้ไม่พัง

  ### ② หน้าเปิดใบเคลม

  1. **ประเภทการเคลม เพิ่มตัวที่ 3 "เคลมหลังตรวจรับ (จากใบ Inspection)"** — ระบบตั้งให้เองเฉพาะใบที่เกิดจากใบตรวจ
     คนเลือกเองไม่ได้ (ช่องถูกล็อก) และมีลิงก์กลับไปใบตรวจต้นทาง · เก็บในคอลัมน์ใหม่ `มาจากใบตรวจ`
  2. **ลักษณะงาน เปลี่ยนคำตามที่สั่ง** — อะไหล่ หรือ อุปกรณ์ / งานซ่อม ไม่มีเปลี่ยนอะไหล่ (ค่าแรงและค่าใช้จ่ายอื่น ๆ) /
     อะไหล่ หรือ อุปกรณ์ และ งานซ่อม
  3. **ชนิดงาน ตปท. ตัดคำว่า (ผ่านสโตร์/ไม่ผ่านสโตร์) ออก** เหลือ **Tankers** กับ **อะไหล่ หรือ อุปกรณ์**
     ใบที่มาจากใบตรวจ ระบบเติมให้เองตามใบตรวจต้นทาง · หน้าใบที่บันทึกแล้วก็มีช่องนี้แล้ว (เดิมไม่มี)
  4. **สถานที่ผลิต = ในประเทศ → ไม่มี CHASSIS ผู้ผลิต และไม่มี E. No.** ซ่อนทั้งคู่ พร้อมล้างค่าที่ค้างไว้
     ทำเหมือนกันทั้งหน้าเปิดใบใหม่และหน้าใบที่บันทึกแล้ว

  ### ③ หน้าเปิดใบตรวจรับสินค้า

  1. **แม่แบบเช็คลิสต์** ดึงจากทะเบียนแล้ว · เลือกได้เฉพาะแม่แบบของลักษณะงานที่เลือก · บอกจำนวนหัวข้อและจำนวนรูป STD
  2. **เพิ่มช่องลักษณะงาน** — Tankers / อะไหล่ หรือ อุปกรณ์
  3. **เพิ่มช่อง E. No. ต่อจาก CHASSIS ผู้ผลิต** (ในประเทศซ่อนทั้งคู่ กติกาเดียวกับใบเคลม)
  4. **ตอบคำถามเบียร์: "ชนิดงาน รู้ได้เองจากลักษณะงานใช่ไหม" → ใช่** เลยรวมเป็นช่องเดียว
     ไม่ต้องกรอกซ้ำอีกช่อง (คอลัมน์ในชีตยังชื่อ "ชนิดงาน" เหมือนเดิม ข้อมูลเก่าไม่พัง)

  ### แก้ของเดิมที่เป็นระเบิดเวลา

  · `INSP_FIELD_COL` ใช้ **เลขคอลัมน์ตายตัว** (area:4 kind:5 … note:19) — เพิ่มคอลัมน์ทีไรจะเขียนผิดช่องแบบเงียบ ๆ
    เปลี่ยนเป็นอ้างด้วยชื่อหัวตารางผ่าน `colOfI_()` แล้ว · `sendUnAccToClaim` ก็เลิกใช้เลข 17/18 แล้วเหมือนกัน
  · `sendUnAccToClaim` อ่านหัวใบตรวจแค่ความยาว `HDR_INSP` — คอลัมน์ที่เพิ่มทีหลัง (E. No.) จะหลุด แก้ให้อ่านเต็มความยาว
  · ข้อความ "ก่อนส่งมอบ / หลังส่งมอบ" เคยเขียนกระจาย 6 ที่ — ใบประเภท insp เลยโผล่เป็น "หลังส่งมอบ" ผิด ๆ
    รวมเป็นตัวแปลงเดียว `claimTypeText_()` (หลังบ้าน) และ `claimTypeShort()` (หน้าเว็บ)
  · ช่องข้อความยาวในฟอร์มเคยดันคอลัมน์จนล้นการ์ด — ใส่ `min-width:0` กันไว้ทั้งระบบ

  **คอลัมน์ที่เพิ่ม (ต่อท้ายเท่านั้น)** — ใบตรวจ: `E. No.` · `รหัสแม่แบบ` · ใบเคลม: `มาจากใบตรวจ`
  มีเทสต์ล็อกลำดับคอลัมน์เดิม 22 ช่องแรกของใบตรวจไว้แล้ว
