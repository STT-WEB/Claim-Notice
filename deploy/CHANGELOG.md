- **v1.0.0** (4 ก.ย. 2569) — **หน้าแรกเป็นเมนู 5 แท็บแบบ NOVA + ลายเซ็นสดตามคนที่กด**

  **หน้าแรกใหม่ = 5 แท็บ ตามที่เบียร์สั่ง** (แทนหน้าแรกเดิม)
  ① เปิดใบขอเคลม · ② อนุมัติใบเคลม · ③ งานสโตร์ · ④ งานจัดซื้อ · ⑤ อนุมัติ ปิดจบ
  · แต่ละแท็บมี **ตัวเลขใบที่ค้างอยู่ในขั้นนั้น** · แท็บที่เป็นงานของคุณมี ✋ กำกับ
  · กดแท็บ = เห็นรายการใบที่ค้าง กดที่แถวเข้าใบได้เลย · ใบตรวจรับกับรายงานย้ายไปเป็นปุ่มด้านบน

  **เปิดใบขอเคลมมี 2 ปุ่ม** — เบียร์: *"ข้อมูลไม่ครบ ... พอกรอกเสร็จ มีปุ่มบันทึกร่าง และปุ่มส่งอนุมัติได้เลย"*
  · **💾 บันทึกร่าง** — ขอแค่เลขที่ JOB (ระบบต้องใช้ออกเลขเอกสาร) ที่เหลือขาดได้หมด กลับมาเติมทีหลัง
  · **📤 บันทึก + ส่งอนุมัติ** — ตรวจครบทุกช่อง + ทุกรายการต้องมีรูป แล้วส่งขออนุมัติในคำสั่งเดียว
    ถ้าบันทึกได้แต่ส่งไม่ผ่าน ระบบบอกเหตุผลและ**เก็บใบไว้เป็นร่างให้** ไม่หายไปไหน

  **ลายเซ็นขึ้นเองตามคนที่กด** — เบียร์: *"ลายเซ็นตั้งแต่ผู้เปิดใบ ผู้อนุมัติ ก็จะขึ้นมาเลย
  พอถึงสโตร์กด ก็จะมีลายเซ็นสโตร์คนนั้นได้เลย"*
  · 5 ช่อง: ผู้เปิดใบ · ผู้อนุมัติ · สโตร์ · จัดซื้อ · ผู้ปิดงาน
  · เก็บเป็น **ชื่อ · แผนก · วันเวลา** เซ็นทันทีที่คนนั้นกดรับ/อนุมัติ/ส่งต่อ · **เซ็นแล้วทับไม่ได้**
  · ขึ้นทั้งบนหน้าใบและ**บนเอกสารที่ปริ้น** — ช่องที่ยังไม่ถึงคิว เว้นเส้นเซ็นมือไว้เหมือนเดิม

  **ปิดงานเป็นของผู้บริหาร** — ขั้น ⑤ QC ตรวจของที่กลับมาได้ แต่**คนกดปิดงานต้องเป็นผู้บริหาร**
    (เพิ่ม `nextRoles` ในตัวขั้นตอน — คนกรอกกับคนกดส่งต่อไม่จำเป็นต้องเป็นคนเดียวกัน)

  **ตรวจก่อนส่งให้เบียร์** — ชุดทดสอบ **59 ข้อ ผ่านหมด** · เช็คลิสต์ตามคำสั่งเบียร์ **9 ข้อ ผ่านหมด**
  (วัดจากหน้าจอจริง: 5 แท็บครบ · ตัวเลขค้าง 2/1/1/0/0 ตรง · กดสลับแท็บแล้วรายการเปลี่ยนจริง ·
   2 ปุ่มขึ้นถูก · บันทึกร่างผ่านทั้งที่ข้อมูลไม่ครบ · ลายเซ็นขึ้น 2 ช่องแรกพร้อมแผนกและเวลา ·
   หน้าปริ้นโชว์ลายเซ็นที่เซ็นแล้ว) · ไล่ครบ 16 หน้า **0 JavaScript error**

- **v0.9.0** (4 ก.ย. 2569) — **รื้อ Flow ใหม่ทั้งชุดให้ตรงตามที่เบียร์อธิบาย (แบบ BOM ใน NOVA)**

  **Flow เดิมผมทำผิด** — ไม่มีขั้นร่าง ไม่มีขออนุมัติ ไม่มีกดรับเรื่อง สโตร์กับจัดซื้อเห็นใบร่างหมด
  เบียร์: *"ทำไมข้อมูลไม่เป็นไปตาม Flow ที่คุยกัน"* — ถูกครับ ผมทำไม่ครบ

  **ขั้นตอนใหม่ 7 ขั้น**
  1. **ร่าง · ทีมงานกรอก** — Production / Sales / QC / Design กรอกข้อมูลตัวเอง + รูป
     **เซฟค้างไว้ก่อนได้** · ช่องของสโตร์ยังไม่ต้องกรอก · **สโตร์กับจัดซื้อยังไม่เห็นใบนี้**
     (เห็นได้เฉพาะคนเปิดใบ · คนแผนกเดียวกัน · ผู้บังคับบัญชา · ผู้บริหาร)
     — รองรับกรณีถ่ายรูปหน้างานตอนไป Onsite แล้วค่อยมากรอกต่อ
  2. **รอผู้บังคับบัญชาอนุมัติ** — กด "ส่งขออนุมัติ" แล้วเด้ง LINE หา Approver · อนุมัติ หรือ ตีกลับให้แก้
  3. **สโตร์รับเรื่อง · เติมข้อมูล** — **ต้องกด 📥 รับเรื่องก่อน** ช่องถึงจะเปิด แล้วเติมเลขใบส่งมอบ · PO · Supplier
  4. **จัดซื้อรับเอกสาร · ตรวจ** — **ต้องกด 📥 รับเอกสารก่อน** แล้วตรวจ → Accept หรือ **ตีกลับไปต้นน้ำ**
  5. ส่ง Supplier · รอคำตอบ  6. รับของกลับ + QC  7. ปิดงาน
  · ระบบจำว่า **ใครกดรับ เมื่อไหร่** และเปลี่ยนขั้นทีไร ต้องกดรับใหม่ทุกครั้ง

  **ยกเลิกใบเคลม — เบียร์เท่านั้น** ต้องบอกเหตุผล · ใบที่ยกเลิกหายจากทะเบียน แต่ข้อมูลยังอยู่ในไฟล์

  **หน้าแรกช้า** — หน้าแรกต้องนับของทั้งระบบซึ่งกินเวลาจริง
  → **วาดหน้าให้ก่อนเลยด้วยตัวเลขล่าสุดที่จำไว้ กดใช้งานได้ทันที** แล้วค่อยเติมตัวเลขจริงทีหลัง ·
    แคชยาวขึ้นเป็น 3 นาที (มีคนสร้าง/ส่งต่อ/ยกเลิกใบเมื่อไหร่ ระบบล้างแคชให้เอง ตัวเลขจึงไม่ค้าง)

  **ตรวจคำแปล เป็นแผงลอยชิดขวา** — เบียร์: *"อยากให้เป็น POP Up เล็กๆ ด้านข้าง ไม่ต้องเปิดหน้าจอใหญ่"*
    กว้าง 400px เลื่อนอ่านในตัวเอง หน้าหลักยังกดใช้งานต่อได้ · หัวแผงบอกเลยว่าต้องดูอีกทีกี่แถว

  **ส่งรูปให้ Supplier — ผมทำผิดรอบที่แล้ว** ไปให้ "ก๊อปลิงก์" ทั้งที่เบียร์ต้องการ**ตัวไฟล์รูป**
    → ตอนนี้เป็น **⬇️ ดาวน์โหลดรูปทั้งหมดเป็นไฟล์ .zip** ไฟล์เดียวจบ ลากเข้า LINE / แนบอีเมลได้เลย
      และมีปุ่ม ⬇️ ใต้รูปแต่ละใบ สำหรับโหลดเฉพาะรูปนั้น

  **หัวตารางรายการ** — ดำเข้ม #111 · 13px · ตัวหนา · **จัดกึ่งกลาง** ตามที่เบียร์ขอ

  **ตรวจแล้วเองก่อนส่ง** — ชุดทดสอบทั้งโปรแกรม **47 ข้อ ผ่านหมด** เดินครบวงจริง:
    ใบร่างสโตร์/จัดซื้อไม่เห็น → ส่งขออนุมัติ → สโตร์กดอนุมัติแทนไม่ได้ → หัวหน้าอนุมัติ →
    สโตร์เห็นใบแล้ว → ยังไม่กดรับเรื่องกรอกไม่ได้ → กดรับ → กรอกได้ → สโตร์แก้ช่องทีมงานไม่ได้ →
    จัดซื้อช่วยใส่ PO ได้ → ส่งให้จัดซื้อ → จัดซื้อรับเอกสาร → ตีกลับต้นน้ำ → เดินครบวงกลับมา Accept →
    ยกเลิกได้เฉพาะผู้บริหาร · มัดรูปเป็น zip ได้ · และเปิดจริงในเบราว์เซอร์ 0 error

- **v0.8.0** (4 ก.ย. 2569) — **บังคับ flow จริง · ใช้บนมือถือหน้างานได้ · ตอบคำถามที่ค้างอยู่**

  **สถานะ — ใครเป็นคนเปลี่ยน? คำตอบคือ ไม่มีใคร ระบบเปลี่ยนให้**
  · เดิมมี 2 อย่างซ้อนกัน คือ "สถานะ" (เลือกเอง) กับ "ขั้นตอน" (ระบบ) → สับสนว่าอันไหนจริง **ผมออกแบบซ้ำเอง**
  · ตอนนี้ **สถานะเดินตามขั้นตอนเสมอ** ขั้น 1-3 = ร่าง · ขั้น 4 = ส่ง Supplier แล้ว ·
    ขั้น 5 = Supplier ตอบแล้ว · ขั้น 6 = ปิดงาน · ช่องเป็นแบบอ่านอย่างเดียว แก้มือไม่ได้ทั้งหน้าเว็บและหลังบ้าน

  **ผู้บริหาร (ADMIN) ก็ต้องล้อตามกฎ** — เบียร์: *"ถึงเบียร์จะเป็น Admin ก็ต้องล้อตามกฎที่วางไว้นะ"*
  · เดิม ADMIN ผ่านทุกด่าน → เวลาเบียร์ทดสอบเลยไม่เห็นขั้นตอนอะไรเลย เหมือนระบบไม่มี flow
  · ตอนนี้ ADMIN **ทำงานแทนแผนกไหนก็ได้** (ไว้ช่วยงานตอนคนไม่อยู่) แต่ **ข้ามลำดับขั้นไม่ได้** เหมือนคนอื่น
    ต้องกดปุ่มส่งต่อทีละขั้นจริง ๆ · มีข้อยกเว้นเดียวคือแก้เรทที่ล็อกไว้ ซึ่งเป็นกฎที่เบียร์สั่งเองแต่แรก

  **ปริ้นแล้วล็อก** — ปริ้น**ฉบับที่ส่งออกไปข้างนอก** (แจ้งเคลม / เรียกเก็บ) ระบบถามยืนยันก่อน แล้วบันทึกว่าใบนี้ออกไปแล้ว
    → **เพิ่มรายการสินค้าไม่ได้อีก ต้องเปิดใบใหม่** · ฉบับภายในปริ้นดูกี่รอบก็ได้ ไม่ล็อก (ยังไม่ถึงมือใคร)

  **ใช้บนมือถือหน้างานได้** — เบียร์: *"หน้างานเค้าอาจจะถ่ายรูปจากหน้างานจริงได้เลย"*
  · ช่องกรอกเรียงลงมาทีละช่อง · ตัวหนังสือช่องกรอก 16px (iPhone จะได้ไม่ซูมเอง) · ปุ่มสูง 42px กดด้วยนิ้วได้
  · ตารางรายการเลื่อนซ้ายขวาได้ ไม่ดันจอพัง · **ปุ่ม 📷 ถ่ายรูป เปิดกล้องหลังตรงนั้นเลย** (โผล่เฉพาะจอสัมผัส)
  · วัดจริงบนจอ 390×844: **ไม่มีล้นแนวนอน · ปุ่มไม่ทับการ์ด · 0 JavaScript error**

  **รูปจะส่งให้ Supplier ยังไง** — เพิ่มปุ่ม **📤 ส่งรูปให้ Supplier** บอก 3 ทางในหน้าเดียว
